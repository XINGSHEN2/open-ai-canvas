# 单容器源码部署可靠性

本文仅针对已有的内网单容器源码部署，不替代官方 Compose / Host Updater 流程。

## 前后端进程

先在隔离目录构建后端和前端，再更新运行产物。启动脚本不联网安装、不现场编译；使用 `scripts/runtime-supervisor.py` 同时管理两个独立进程组。任一服务退出时停止同组部署的另一服务并非零退出，由容器 `unless-stopped` 策略恢复。手动停止容器不会自动拉起。

- `CANVAS_APP_DIR`：源码目录，默认 `/app`。
- `CANVAS_RUNTIME_DIR`：仓库外工具/日志目录，默认 `/runtime`。
- `CANVAS_BACKEND_BINARY`：已构建、带版本的可执行文件。
- `CANVAS_RUNTIME_ENV_FILE`：可选运行环境 JSON（字符串映射），权限 0600，仓库外保存。部署时保留实际运行服务配置，禁止输出密钥。
- 启动前保存源文件、旧构建、旧启动脚本和 SQLite 在线备份；更新前比较基线，出现同期修改必须停止覆盖。
- 发布静态文件时保留上一版本哈希 assets，避免已打开页面的懒加载 chunk 失效。

## H3

H3 使用 mx-services 的 profile 入口和持久化队列；可安装该仓库 `hybrid/recovery` 下的 systemd timer。仅在显式启用标记存在时检查已验证 PID，API 故障只恢复 API，模型主进程退出才尝试恢复模型。显卡被其他服务或遗留 rank 占用时拒绝重复启动，不任意杀 GPU 进程。手动 stop 关闭自动恢复。

网站 MiniMax 查询超时只恢复已有上游任务，不重复 POST。H3 v2 查询可额外返回 progress/current_step/total_steps/queue_position，原有字段与端口保持不变。

## Qwen 图片任务

本地 `qwen-image-2.1` 渠道使用 Images 兼容接口的可选 `Prefer: respond-async` 扩展。服务先将任务写入原有 FIFO，再返回 202 和上游任务 ID；网站必须先持久化该 ID，随后查询同一任务并将结果保存到网站资源库。普通不带该请求头的调用仍同步返回 OpenAI Images 的 `data`，不改变原有端口和请求字段。

- 无参考图使用 JSON `/images/generations`；有参考图使用 multipart `/images/edits`，保留 `n=1` 和文件顺序。网站的 1K/2K 档位最终转换为具体像素，不把档位名称当作尺寸传递。
- 单次等待超时或短暂状态查询失败不重新 POST。已有上游 ID 的任务继续回查原任务；每轮连续 5 次瞬态错误后释放 worker，15 秒后继续原任务，整体回查最多持续到首次开始时间后 1 小时。真实失败、取消和永久参数/权限错误不吞掉。上游接纳状态不明且没有任务 ID 时不自动重提。
- 图片交付有独立检查点：生成成功后的临时下载失败重试下载，不重新推理。任务记录保留上游 ID，便于排查。
- 图片服务发布前同时检查网站任务、模型队列与 Worker；更新后按 1K 文生图、双参考图、带 EXIF 旋转的 JPEG、2K 出图和普通账号下载分别验收。协议 mock 不能代替真实推理，真实推理也不能代替浏览器逐入口操作。

## 验收与回滚

部署前确认网站 worker 和 H3 队列空闲。部署后验证 ready、普通用户注册/会话/目录、素材上传、章节及镜头、任务入队、生成产物关联和下载。保留测试记录于运行目录，不提交密码、Cookie、数据库或视频。

回滚时先停目标容器，恢复备份的源码/静态文件及启动脚本，切回旧二进制后启动；不要覆盖部署后新增数据库数据。此次无数据库 schema 变更。容器受控重启不等同于主机断电演练；进程退出监管不检测进程存活但卡死的情况。
