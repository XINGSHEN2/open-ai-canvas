# Gitee MiniMax-H3

这是独立渠道 `gitee-h3-video`，不替换本地 H3。模型菜单提供三个明确入口：参考生视频（`ref2va`）、文生视频（`t2va`）、首尾帧生视频（`fl2va`）。

- 创建：`/v1/async/videos/generations`；查询：`/api/v1/task/{id}`。
- 开放 6 秒、16:9、20 步、seed=0。分辨率由上游决定，不宣称支持本地的 480P/768P 切换。
- 文生视频不允许携带素材，不上传 Litterbox、不显示素材上传确认。首尾帧需要恰好两张图片，不能混入视频或音频；默认第 1 张首帧、第 2 张尾帧，显式画布帧绑定或图片角色优先。后端再次验证，缺帧、重复帧和模式混用在上传前失败。
- 文生视频请求不包含 `cond_*` 或帧字段；首尾帧仅发送 `first_frame/last_frame`；参考生成仅发送非空 `cond_image/cond_video/cond_audio`，保留图片编号顺序。
- API Key 使用原有后台渠道加密配置，不放前端或提交到仓库。
- 提交前弹窗提示并要求用户同意：参考素材将交给 Litterbox 第三方公网临时托管，设置 12 小时。链接持有人可能读取素材；不适用于敏感素材。
- 后端校验资源归属；只读取本站已上传资源。图片、视频和音频保持原顺序；一次处理一份，单文件限制 100 MiB。上传失败不创建上游视频任务。
- 不做跨用户缓存，不修改本地原文件；结果沿用现有任务下载和持久化流程。
- 12 小时是上游保留参数，不是本平台对删除时间或可用性的保证。失败前已上传的素材也会保留至过期。
- 后台任务恢复已有上游 ID 时仅查询，不重复上传或创建计费任务。

参考模式已通过普通账号单图生成、回存与下载。新增文生与首尾帧模式需单独验收；浏览器三个入口、多图/视频/音频仍需分别确认。

部署时运行 `package.py` 生成插件包，通过 `backend/cmd/provision-gitee-h3` 的管理服务配置渠道；密钥从现有 `MOARK_API_KEY` 环境变量读取。工具需要显式 `--apply --provider-billed PROFILE_DIR`，且应先备份数据库。当前站内积分为零，上游费用由配置账号承担，可在原有后台修改定价。
